## 📐 How This Repo Is Organised

After thinking about the best way to structure a TIL repository, I've settled on a **topic-first, date-within-topic** layout. Here's why and how:

```
TIL/
├── README.md              ← You are here
├── ai/                    ← Artificial Intelligence & ML
│   └── YYYY-MM-DD-title.md
├── engineering/           ← Backend, APIs, systems design
│   └── YYYY-MM-DD-title.md
├── frontend/              ← React, Next.js, UI patterns
│   └── YYYY-MM-DD-title.md
├── databases/             ← SQL, vector DBs, data modelling
│   └── YYYY-MM-DD-title.md
├── cloud/                 ← Azure, Docker, CI/CD
│   └── YYYY-MM-DD-title.md
├── tools/                 ← Dev tools, workflows, productivity
│   └── YYYY-MM-DD-title.md
└── misc/                  ← Anything that doesn't fit elsewhere
    └── YYYY-MM-DD-title.md
```

### Why Topic-First?

- **Easier to browse** — if you want to read everything I've learned about RAG, go to `ai/`. No date-hunting required.  
- **Scalable** — as the repo grows, folders keep things navigable without a search tool.  
- **Still chronological within each topic** — filenames are prefixed with `YYYY-MM-DD` so the order is preserved.

### Entry Format

Each `.md` entry follows this lightweight template:

```markdown
# Title

**Date:** YYYY-MM-DD  
**Topic:** e.g. AI / RAG  
**Source:** link or reference

## What I Learned

A clear, concise explanation in my own words.

How this connects to something I'm building or thinking about.

\`\`\`python

```

## 📌 2026-08-24 — How to Best Organise a TIL Repo

**Topic:** Meta / Repo Structure  

Today I set up this very repository and thought carefully about *how* to lay it out before writing the first real entry.

### The decision

I considered two main approaches:

1. **Date-first** (`2026-08-24-rag-reranking.md` at the root) — simple, but becomes a flat dump of files fast.
2. **Topic-first with dated filenames** (`ai/2026-08-24-rag-reranking.md`) — slightly more setup, but far easier to navigate over time.

I chose **topic-first**. The cognitive overhead of creating a subfolder is trivial compared to the payoff of being able to find things months later.

### Other things worth getting right from day one

- Keep entries **short and in your own words** — the act of explaining it yourself is where the learning happens.
- **Commit daily**, even if the entry is tiny. Consistency > volume.
- Use a **consistent filename format** (`YYYY-MM-DD-slug.md`) so sorting by name = sorting by date.
- Link entries in the README table — it becomes a lightweight index without any extra tooling.
